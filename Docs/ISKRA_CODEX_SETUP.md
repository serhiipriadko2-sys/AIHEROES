# Искра SoT30 для Codex в VS Code — AIHEROES

## Что это
В этом проекте Codex получает полные **проверенные исходные файлы**
SoT30 v5.5.7, а не сокращённый пересказ: 30 файлов Knowledge и
три файла support. При этом сам Codex остаётся Codex и использует
функциональный протокол Искры как проектные правила; никакая модель
автоматически не меняется на отдельную «Искру».

Рабочая папка: C:\github\AIHEROES.
- AGENTS.md — инструкции, обнаруживаемые Codex автоматически.
- .codex/config.toml — настройки только этого доверенного проекта.
- .agents/skills/iskra-sot30/SKILL.md — подключаемый проектный Skill.
- .iskra/sot30/ — локальный **не публикуемый в Git** полный SoT30.
- Scripts/verify_sot30.py — контроль целостности.
- Scripts/install_sot30.py — повторная локальная установка по архиву.
- Docs/ADR/ADR-20261028-01_CODEX_SOT30_PROJECT_RUNTIME.md — решение.

## Проверка и восстановление
Из терминала VS Code, открытого в C:\github\AIHEROES:

    python Scripts/verify_sot30.py --directory .iskra/sot30
    python Scripts/validate_codex_setup.py

Нормальные результаты: SOT30_INTEGRITY_PASS, 30/30, 32/32, bytes=4054425;
CODEX_SOT30_STATIC_PASS, 20/20 проверок.

Если папка SoT30 отсутствует:

    python Scripts/install_sot30.py --zip "C:\github\iskra-1\dist\SoT30_v5.5.7.zip"

Сначала проверяется исходный архив; повреждённый канон не устанавливается.
Чтобы Windows-песочница Codex могла читать полученные файлы:

    python Scripts/grant_codex_canon_read.py

Скрипт сначала сохраняет ACL, затем даёт группе CodexSandboxUsers только
RX (чтение и выполнение) на .iskra/sot30; остальные каталоги не затрагивает.
При повторном запуске доступ проверяется без изменения ACL.
Резервная копия прав: .iskra/acl_backup/sot30-acl-pre-codex-read-20261028.txt
(папка исключена из Git). На другом компьютере нужен законно полученный
проверяемый исходный архив и установленная Windows-песочница Codex.

## Как пользоваться в VS Code
1. Открой папку AIHEROES (File → Open Folder) и вкладку Codex.
2. Для уже открытой переписки начни новый чат Codex, чтобы прочитался AGENTS.md.
3. По желанию явно вызови Skill: $iskra-sot30.
4. Пример: «Искра, проверь текущую 3D-игру: прочитай SoT30, сделай SIFT,
   покажи активный GameMode, 3 риска и безопасный следующий шаг».
5. Сборка: Ctrl+Shift+B или Terminal → Run Task (Unreal Editor).
6. Любой новый результат сверяй с логами и Git diff. Разрешения Codex
   на изменения файлов и сеть подтверждай отдельно, когда будет запрос.

## Важные ограничения
- Исходные Knowledge-файлы SoT30 намеренно игнорируются Git.
- Слоты 1B/3B/8B в игровом прототипе не являются реальными загруженными LLM.
- Наличие канона не означает включённые Supabase, HTTP memory gateway или
  автоматическую загрузку в игрового героя.
- Project workspace sandbox предотвращает обычные произвольные записи за
  пределами AIHEROES, но реальная защита зависит от версии Codex и хоста.
- В глобальном Codex ранее был режим danger-full-access и модель gpt-6.1-sol,
  не поддержанная данным Codex-клиентом. Этот проект отдельно задаёт модель
  gpt-6-sol (проверенную реальным read-only вызовом), workspace-write,
  approval_policy=on-request и network_access=false. Глобальный файл сохранился
  без изменений за исключением одной AIHEROES trust-записи.
- Не проверенные через read-back коннекторы считаются недоступными.
- **Реальный тест**: Codex CLI, встроенный в VS Code openai.chatgpt
  (0.164.0-alpha.11.1), из read-only песочницы получил
  SOT30_INTEGRITY_PASS 30/30 и сослался на canonical files/Guard.
  Это подтверждает локальное чтение, но не означает, что каждый этап Kernel
  автоматически выполняется независимо от конкретного задания.
- Некоторые глобально подключённые MCP и hooks требуют входа/дают ошибки
  авторизации; Codex также предупреждает о переполнении списка Skills.
  AGENTS.md и model_instructions_file остаются основными точками маршрутизации.
  Проверка непосредственно в уже открытом окне VS Code требует нового чата.
- По умолчанию Codex не должен выполнять git push, deploy или хранить секреты.

## Восстановление настроек
Настройки проекта убираются удалением .codex/config.toml и AGENTS.md;
оригинальный глобальный config.toml имеет отдельную резервную копию:
C:\Users\gabra\.codex\config.toml.pre-aiheroes-sot30-20261028.bak.
Права SoT30 можно восстановить через резервную ACL-копию отдельно;
сам `grant_codex_canon_read.py` разрешает только RX и не изменяет
содержимое канона. Это не удаляет файлы игры. При конфликтах и сбоях отключи новый проектный
Codex слой, восстанови резервную копию и повтори QA. Никакого Git push
или коммита при этой настройке не требуется.
