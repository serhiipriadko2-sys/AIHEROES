# AIHEROES — сначала одна законченная кампания

Дата: 29.10.2026. **Основа выбрана пользователем:** основная кампания, сначала
законченный игровой цикл. **Статус этого дизайна: кандидат на согласование**;
выбор основы не объявляется согласием со всеми решениями ниже.

## A. Результат для игрока

Обычный запуск открывает одну понятную стратегию, а не набор демонстраций.
Первую партию можно начать без чтения технических отчётов и пройти по цепи:

**Цель → подготовка на базе → разведка и маршрут → подтверждённое нападение
→ наблюдаемый автобой → понятные потери/награда → развитие героя
→ завершение кампании → сохранение и восстановление.**

Ориентир первой сессии — 20–30 минут как **дизайн-гипотеза**, не измеренная
продолжительность и не повод тайно менять цены или силу охраны.

## B. Что уже установлено по исходникам

- `Config/DefaultEngine.ini` выбирает `AIHeroesGameMode`: пять объектов,
  действующий Grid V2 и существующие сохранения. Это выбранная основа.
- `ZoneExpedition` богаче маршрутами, но имеет отдельные состояние, интерфейс
  и жизненный цикл. Она остаётся источником будущих интеграций, не новым
  стартовым режимом этого среза. `AIH*` также не удаляется.
- `AIHeroesCampaignObjectives.cpp` содержит четыре условия: экономика,
  освобождение территории, протоколы и тематический слот модели.
- `AIHeroesExplorerHUD.cpp:149–154` выбирает подсказку другой логикой: после
  владения ORE предлагает архив, не учитывая остальные незавершённые условия.
  При ином порядке захватов возможна рассинхронизация даже с первым условием.
- В том же HUD кнопка «Развитие [Y]» имеет action203. В
  `AIHeroesPlayerController::HandleHudAction` этот action открывает read-only
  Protocol Lab. Покупки протоколов и слота уже находятся в BasePanel.
- База, досье и карта используют разные визуальные/языковые представления.
  Это наблюдение исходников, не свежий визуальный аудит работающего окна.

## C. Выбранный подход и альтернативы

1. **Выбранная основа:** довести основной режим, переиспользуя его бой,
   экономику и сохранения. Цена — сначала небольшая карта; выгода — меньше
   разрывов между существующими работающими действиями.
2. Процедурная экспедиция первой: больше маршрутов сразу, но нужно отдельно
   соединять прогрессию, бой и сохранения. Пользователь её не выбрал для этого
   этапа; это не запрет на последующее расширение карты.
3. Ещё один GameMode/универсальный переписанный движок: отклонён как предложение
   разработчика — добавит третью поверхность вместо законченного игрового пути.

## D. Предлагаемый первый интеграционный срез

### 1. Правда интерфейса — до новых возможностей

- Единый источник текущей цели — существующий CampaignObjectives. Компактная
  подсказка на карте и подробное досье не выбирают разные следующие этапы.
- Русское краткое представление не парсит английские строки `NextAction`.
  Нужен явный идентификатор следующего этапа, производный от тех же проверок,
  без новых полей SaveGame. Структура и названия API — решение реализации.
- «База и развитие» ведёт к существующей панели покупок. Сравнение протоколов
  подписывается как сравнение тактик, не как покупка улучшения. Старые горячие
  клавиши сохраняют назначение; новые автоматические покупки не появляются.
- На старте ясны три действия: выбрать известную цель, спросить героя,
  подтвердить переход/нападение. При нехватке хода/ресурсов показана причина.

### 2. Цена результата — в существующих экранах

После боя показывать проверенные потери, оставшуюся армию, уже применённую
награду и следующее возможное действие. Переиспользовать досье/результат,
не создавать ещё один независимый журнал. Ничего не начислять при просмотре.
Старым записям не дорисовывать отсутствующую историческую награду.

Это следующий небольшой срез после пункта1, не обязательство одновременно
переписать все представления и форматы записей.

### 3. Визуальная цельность, а не количество декораций

Существующее направление Amber March остаётся основой. Карта, база, досье
и бой должны говорить одинаковыми цветами состояния, терминами и иерархией:
цель → армия/риск → основное действие → второстепенное меню.
Рельеф и здания не закрывают выбор объекта; дороги читаются; текст не
теряется на фоне. Художественные улучшения допускаются только вместе с
проверкой этого игрового пути, не как замена ей.

Новые ReliefV5/ArchitectureV6 и чужие незавершённые правки сохраняются.
Их наличие на диске не является доказательством текущего gameplay PASS.

## E. Приёмка и порядок

1. Сначала пункт D1: небольшой source diff и regression-тесты подсказок/действий.
2. Сборка, вся актуальная группа `AIHeroes`, затем графическая проверка того же
   снимка исходников/DLL. Не использовать старое число тестов как признак успеха.
3. Один непрерывный прогон: новая кампания → подготовка → захват шахт → развитие
   → охраняемые цели → все существующие условия победы → save/load.
4. Отдельно: поражение, восстановление армии допустимым способом, повторный бой,
   нехватка ходов/ресурсов, повторный callback и открытие/закрытие окон.
5. Связанный набор кадров одной сборки: карта, база, совет, бой, результат,
   победа и восстановленная кампания. Сравнивать несколько размеров окна только
   при одном DLL/seed; Windows touch-прокси не считать Android-приёмкой.

PASS возможен только для проверенного среза. Зелёная компиляция не означает
играбельность, а количество тестов — понятность и красоту интерфейса.

## Инварианты, ограничения и цена

- Игрок решает стратегию и покупки; герой самостоятельно командует боем.
- Нет нового режима по умолчанию, LLM-checkpoint, фракций, магии, мультиплеера
  или расширения карты в первом срезе. Это осознанная отсрочка, не удаление.
- Условия победы, цены, прирост, частичные HP, V1/V2, commit и SaveGame не меняются
  без отдельного решения и проверки проходимости. Протокольный ранг ≠ веса модели.
- Приватный SoT30, внешние сервисы, Git-история и пользовательские saves вне diff.
- Нативная QA из этой сессии пока ограничена отказом сервиса согласования
  команд (`workspace is out of credits`). Локальные задачи VS Code доступны
  для самостоятельного запуска пользователем; обход разрешений не предлагается.
- Rollback — только собственные согласованные hunks; никакого reset/clean,
  удаления чужих ассетов или пользовательских сохранений.

**Граница согласования:** утвердить D1 как первый исполняемый срез; D2/D3 —
очередь следующих малых проходов. Общий приоритет и основа уже выбраны;
детали первого среза ещё не называются реализованными.

ΔDΩΛ: Δ — развитие ограничено единым главным игровым путём; D — выбор
пользователя + активный GameMode + конкретные расхождения HUD/правил;
Ω — 90% для основания дизайна, не для ещё не выполненной приёмки;
Λ — согласование первого среза, свежая визуальная QA или конфликт исходников.
