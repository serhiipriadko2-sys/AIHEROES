# Amber March / Рубежи Искры — первый визуальный проход

Status: PASS_WINDOWS_EDITOR_FIRST_VISUAL_PASS. Final build, 216 automation tests and three graphical runs passed on the recorded snapshot. Actual frames inspected at 1280x720, 960x720 and 640x720; this is not full accessibility or Android acceptance.
Working art direction, not a final game title or an approved full art bible.
Scope: main five-site AIHeroesGameMode. Procedural expedition and battle UI remain separate.

## Product brief

Player: a newcomer to PC/Android strategy, not a developer reading a diagnostic overlay.
Primary outcome: identify a destination, understand its purpose and movement price, ask the hero,
then deliberately confirm the move or battle. The player does not manually command tactical units.
Existing gameplay, economy, road costs, fog, saves and offline/model truth boundaries remain unchanged.

## Setting candidate

Nature has reclaimed a civilisation of learning machines. Human settlements recover old stone
observatories, bronze mechanisms and crystalline archives. The hero is a small travelling automaton
whose amber core gains new cognitive capabilities as the campaign advances.
The world should feel inhabited, curious and recoverable, not a neon terminal or a grey testing room.

Visual language: warm ivory masonry, dark slate roofs, bronze fittings, deep pine greens,
muted teal water, and restrained amber cognition accents. Cyan crystals identify recoverable data.
Large silhouettes identify game functions before text does: citadel, timber mill, quarry entrance,
watchtower, ruined archive. Colours supplement labels; they do not replace ownership text.

## UI hierarchy

Always visible: day/resources, short current objective, four commands (Base, Hero, Ask, End day).
Selected destination: name, ownership/guards, purpose, movement cost and one explicit primary action.
No selection: a short three-step explanation instead of a wall of technical state.
Utilities: Goals, Dossier, Route, Recruitment advice, Camp, Convoy, Save, Load, Slot, Replays live
in a separate menu. Escape closes it without issuing a campaign command.
The full existing base and dossier panels remain functional. Their English copy is not fully localised
by this slice; the new exploration shell uses Russian. Combat/replay controls keep their existing UI.
No direct model-ready or parameter-count claim is added. The new footer states that the advisor is rule-based.

The presentation uses the current Canvas HUD with a separate pure ExplorerLayout. It is NOT a UMG
migration. This limits gameplay/input churn while providing a visible improvement now.
A later UMG/CommonUI pass should implement font-size settings, controller focus and device safe areas.

## Original asset pipeline

Tools/build_amber_art.py generates nine original low-poly FBX files plus an editable .blend under
ArtSource/AmberMarch. A deterministic seed controls the island surface. No outside assets are downloaded.
Tools/import_amber_art.py imports into /Game/AmberMarch using Unreal's editor Python plugin, enabled
only for that commandlet invocation. No project-wide plugin or Windows settings are changed.
The generated palette has no image textures. Original FBX asset_manifest records geometry counts and hashes.
The art source file keeps all models at their origin for deterministic export; it is not a polished scene.

Assets: SM_Hearth, SM_Sawmill, SM_Quarry, SM_Watchtower, SM_Archive, SM_Seeker, SM_Pine,
SM_Boulder, SM_Island. SM_Seeker is a static proxy: no skeleton, walk cycle or facial animation.
SM_Boulder is an available kit piece, not necessarily placed in the first scene.

Runtime decorations do not own gameplay. The original invisible node collider still resolves selection.
Imported node artwork inherits actor fog visibility; refresh never reveals a hidden actor.
Ownership and HQ level remain existing game state; the palette does not fabricate a captured site.
Trees use a shared instanced component. Water and terrain are presentation-only, not new impassable terrain.
No new roads, route prices or resources are generated by the decorative island.

## Validation targets

Four new automation groups under AIHeroes.Visual.Explorer:
- supported/invalid viewport geometry and reserved map area;
- visible action centres map to the correct stable controller IDs, no hidden utility hit targets;
- all nine original assets have geometry, sane centimetre scale and assigned materials;
- visual refresh does not mutate ownership, health, coordinates, collider or fog and does not duplicate components.

Run the full existing automation set, not only the new groups. Run existing actual travel-view smoke
at 1280x720, 960x720 and 640x720 and visually inspect before/after screenshots.
Compiled tests do not establish usability. Android packaging/performance and complete accessibility
remain unverified; editor window tests are not device tests.
