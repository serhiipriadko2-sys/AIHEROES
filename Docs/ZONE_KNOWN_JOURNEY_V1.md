# AI HEROES — Known-Only Journey Planner v1
Дата: 2026-10-29. Режим: отдельная процедурная экспедиция ZoneExpedition.
Статус: локальный Windows-прототип, до отдельной проверки Android и UX.

## A/B. Основание и границы

Официальная документация Horn of the Abyss:
- https://h3hota.com/ru/template-format
- https://h3hota.com/ru/templates

[FACT] В HotA шаблон описывает зоны, связи, дороги, охрану проходов
и плотность объектов. AI HEROES использует только общие идеи о
логистике, разведке и контрольных точках. Никакие чужие фракции,
спрайты, карты, код, тексты, балансовые таблицы или звуки не копировались.

Текущий ZoneExpedition: 7–11 зон, 8 очков движения за день, герой
исполняет только отдельно подтверждённый приказ, бой автоматически
рассчитывается Grid V2. Игровые правила не поддерживают списание
"части пути сейчас, остального завтра" внутри одного приказа.
Кратчайший маршрут ценой 9 не является законным приказом при лимите 8.

Нажатие **I** в активной ZoneExpedition показывает READ-ONLY JOURNEY:
- ближайшее реальное действие игрока (подтверждение движения или End Day);
- самый ранний день прибытия *при условии* допустимости будущих действий;
- число отдельным образом подтверждаемых переходов;
- число ручных переходов к следующему дню;
- предупреждение о неизвестном исходе боя на охраняемой цели.

На Android этот просмотр пока НЕ имеет отдельной экранной кнопки:
задача на следующий интерфейсный проход. Существующие действия с
мышью/касанием, H, Shift+H, D, Enter и Space остаются прежними.

Планировщик начинает работу с Validate -> PlayerView. Дальше
использует только разведанные узлы и направленные связи видимой карты.
Ни одна сырая запись из генератора мира не используется в shipping
входе. Метод PlanVisibleGraphForTests доступен только
WITH_DEV_AUTOMATION_TESTS и дополнительно отфильтровывает
неразведанные узлы и связанные с ними рёбра.

Алгоритм:
1. Отклонить невалидное состояние, закрытую карту или неизвестную цель.
2. При отсутствии живых войск отклонить план на охраняемую конечную цель.
3. Подготовить только законные перемещения между *видимыми* зонами,
   для которых стандартный FAIHeroesAdventurePath даёт Ready при
   доступном дневном бюджете 8.
4. Нельзя предлагать промежуточный пункт, в котором есть живая охрана:
   преждевременная победа над блокпостом не подразумевается.
5. Найти путь по ограниченному состоянию (зона, остаток движения,
   число прошедших дней). Варианты перехода: игрок подтверждает
   целое движение либо игрок вручную заканчивает день.
6. Минимизировать: число дней -> число отдельных подтверждений
   перемещения -> потраченные очки -> лексикографический набор
   известных названий (детерминированное разрешение ничьей).
7. Максимальная глубина просмотра = 14 дней вперёд и 40 шагов.
8. Возвращать только план, никогда не вызывать EndPlayerDay,
   ConfirmPlayerDestination, battle, SaveGame, сеть или нейромодель.

Маршрут не является расписанием гарантированной победы: новая разведка,
неожиданное поражение, изменение армии, сохранённый прогресс, день
365 или переполнение экономики требуют полного пересчёта после
каждого реального шага. ИИ не исполняет приказ сам.

## Границы и откат

В проекте работают несколько параллельных разработчиков.
Этот этап не менял бинарные ассеты Content/AmberMarch, основные
PlayerController/HUD, сетевой код, существующие SaveGame-схемы,
проектные инструкции, GitHub/ветку или секреты. Перед интеграцией
клавиши I исходники GameMode скопированы с проверкой хеша в
Saved/QA/ZoneJourneyIntegrationBefore_20261029/.

Не объявлять DONE для Android, нейромоделей, CI-релиза, подписанного
APK, продакшн-игры, вероятностей победы, независимого ИИ противника
или визуального 3D-боя. Это только offline logistics + PC prototype.

∆DΩΛ: ∆ — легальные многодневные планы по разведанной карте;
D — исходники -> unit/regression -> контрольная DLL -> игровая QA;
Ω — не выше 95% для реально проверенных Windows-сценариев;
Λ — пересмотреть при изменении схемы карты, движка, лимита хода или
получении результатов физических Android-тестов.
